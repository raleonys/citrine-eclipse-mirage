# Next actual selected-Environment integration: read-only plan

Status: planning only after prepare40 Environment2 freeze. No production file edits, compiler/tests, new REA target, target execution, linker or ZIP. This plan does not close the actual two-scope or returned-child-old1 coverage gaps.

## Concrete present composition blocker

Profile::Dependencies.environment (profile.hpp76-101) contains exported type/factory/schedule/copy projections, but no selected owning Environment object. Profile constructor (profile.cpp897-905) populates State::owned_environment ONLY when that entire projection is empty and it constructs its private default provider. Supplying chosen->configuration() explicitly therefore selects the legacy custom projection route and leaves owned_environment null.

That route skips actual Environment.bind at Profile::create945 and dispatches accept/session construction through Policy's legacy virtuals at Profile.cpp601/618-619. The actual concrete session_policy::Policy is final and inherits the default throwing session_environment/accept_environment compatibility methods (profile.hpp53-57). A forwarding sp::Policy wrapper is not a valid shortcut: Application::Impl::Worker::finish_environment_work (profile.cpp283-288) requires dynamic_cast to that exact concrete Policy. Replacing worker bindings/Ports or building a second stand-in application would stop proving the actual selected composition.

A standalone Runtime test App can expose actual WorkerControl, but concrete Policy::worker_returned/close require the real sp::Application lifecycle. A second shadow Profile/Application just to set those flags is rejected as fixture design. Existing EnvFixture/WorkStop is intentionally a lower component fixture and finish_job throws; its second coherent memory/controlled cap cannot be relabeled as actual selected Runtime coverage.

## Minimum legitimate production ownership seam

Add an optional trailing typed shared_ptr<owned_environment::Environment> to session_profile::Dependencies, e.g. environment_owner, with forward declaration only in profile.hpp. Require the old Environment projection to be EMPTY when this owner is supplied, preventing mixed callbacks/owner identity. Profile constructor selects THIS ONE fresh provider, calls its actual configuration(), and retains it in the SAME State::owned_environment field used by bind/session/accept/release/close/clone_environment. Empty owner preserves the present automatic default provider; explicit custom projection without owner preserves existing legacy behavior. Configuration() already rejects a bound/stale provider; no new getter, second Environment or readiness channel is required. original_default_environment remains an automatic-construction choice; an explicitly supplied provider's immutable classifier is deliberate.

For reusing the existing actual Graph/Prepared/NativeThreads scenario, propagate the same optional shared owner through application_graph::ProfileSettings (graph.hpp24-30), then Graph::install server assembly (graph.cpp636-640) into Profile dependencies. It must be a direct forwarding of that SAME owner, not another construction. This is four small production files: profile.hpp/.cpp and graph.hpp/.cpp. Capture their before files together; do not alter Runtime/Policy stop algorithms. No implementation of this seam is part of prepare40 stage.
