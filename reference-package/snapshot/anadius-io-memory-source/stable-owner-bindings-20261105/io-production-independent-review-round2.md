No production edit, compiler, project tests, linker, DLL execution, REA call, ZIP or recorder execution was performed by this review.

Record objects are shared, stable owners of storage descriptors and Concurrent packet bindings. Registry growth copies current metadata after outside-gate preparation and retires replaced containers outside the gate. Serialized keeps its mutable public vectors as the authoritative packet/storage interface, including existing descriptor/packet tamper checks and pointer repair. Concurrent rejects those union catalogs and uses exact owner resolvers; getters supply only passive stable identity, while lookup validates an already admitted Parent actor. Output changes only on Found; the accept overlay uses the actual mode-authoritative packet, not an assumed private Posted operation. `registry_capacity()` observes current coverage rather than the initial size.

The metadata mutex does not span backing allocation/free, variant lifecycle work, SDK range-pin preparation or the recovered opaque handler. Stack Effect reservations exclude same-actor lifecycle reentry and protect a specific busy row, while allowing a different admitted actor to progress. Metadata allocation failures before native allocation do not invent a raw resource; returned/unknown prefixes remain owned. Local LastError preservation separates compiler metadata activity from the actual backing allocation/free result.

Call retains exact Record metadata and its starting generation across the opaque source call. Foreign access to that live generation rejects. Same-actor native cleanup can physically free, cache or reproject the allocation; a new generation is independent of the old Call. Its destructor removes only its own active reservation and releases metadata outside the gate, without inspecting the old projection, slot or generation. This matches actual complete_posted/receive/send and handler/response task code, which copies required locals before storage retirement and does not access the old task after invoking the opaque handler. Holding the Record metadata does not defer native raw free.

SDK review identified a material draft regression at implementation hash `3957a74e0c311a755fe51f6c1be3a2758b6b8c4f1862aac1bdc234b470e4b829`: completion detached the pending range pin before checking the compatibility strong count. The successor retains pending/owner/pin until the outside-gate non-last decrement succeeds. No callback, Parent checkpoint or admission effect occurs between that decrement and the short metadata commit; only then are routing/pending cleared and the range lease reset outside the gate, before the native callback. A failed strong-count guard poisons with the original pending row and lease intact. The complete wrappers include this observation in their catch path and do not replay it.

A second SDK finding identified that including observation in that catch also poisoned the known already-completed eligibility rejection. All three final completion variants now check `completed || unknown` before constructing Call and entering the outcome try/catch. Thus a duplicate cached completion retains its prior rejection without poisoning otherwise healthy IO, while the consumed-strong guard and actual outcome failure still poison. This preserves the unchanged existing duplicate-send-then-cache-drain source case; it has not been executed.
