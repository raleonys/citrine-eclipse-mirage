# Stable socket owner resolver boundary

2026-11-05. SOURCE ONLY, NOT RUN. This author changed only the seven socket files in `socket-resolver-source-hashes.json`. Before bytes and the new header's absent status were captured by root in `before-manifest.json`. No compiler, tests, linking, DLL execution, REA query or ZIP operation was performed.

`OperationStorageResolver::lookup_storage(identity, OperationStorage*&)` and `DispatcherOperationResolver::lookup_operation(OVERLAPPED*, DispatcherOperationBinding*&)` / its typed `CancelOperation*` overload return `MemoryLookup`. Optional owner pointers are appended to PostedEnvironment and DispatcherState; their existing aggregate prefixes, live-span fields and noexcept `current_storage()` / `current_operations()` methods remain intact. By-value nested completion contexts retain the owner pointer automatically.

The new member lookup wrappers use temporary output and commit it only on Found. A nonnull resolver is authoritative on Miss and Ambiguous; neither outcome searches the legacy span. The null-owner route preserves the prior first matching nonnull legacy row, including existing live-span indirection. It does not impose a new duplicate-row rejection on legacy HOST inputs. Both real cache consumers (posted021820 and handler021900) and completion027c10's OVERLAPPED lookup use this boundary. Existing cache-slot clearing, marker writes, free, queued CAS and callback ordering remain unchanged. Completion copies its error/byte/operation values before a callback can end the operation and never rereads its binding afterward.

The unchanged `MemoryLookup` enum moved to neutral `memory_lookup.hpp`. Including write_finish.hpp from completion_dispatcher.hpp would cycle through environment_constructor/composed_write/io_completion/posted_operation; the neutral header resolves that concrete dependency without introducing another lookup framework. Its new file must be included by the next source snapshot/recorder; frozen build/ZIP proofs remain historical.

The resolver owner must validate exact graph/Parent admission, stable descriptor shape and actual payload/operation lifetime. A pointer or successful lookup alone grants no authority, generation proof or lifetime pin. Runtime/Profile/Policy/Environment/Jobs comparisons must bind the exact IO resolver, with existing span checks retained for legacy mode. Root owns those consumers, Runtime construction/Router wiring, CoherentIo admission and OwnedAccept's overlay conversion. OwnedAccept needs the base's stable packet accessor by exact storage before its alternate accept operation is published; the operation resolver must include that actual public binding, rather than assuming every base reservation remains a Posted operation.

This boundary does not enable Original concurrent actors. Stable storage/packet addresses do not synchronize arbitrary mutation or remove upper Profile/Graph/provider gates. In particular, OwnedAccept currently retains its own gate across SDK/effect and Task invocation; combined per-invocation integration must address that independently. No complete same-session progress or native ABI equivalence is claimed.
