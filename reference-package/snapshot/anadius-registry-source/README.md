# Registry callbacks and shared value helpers

This is a partial, independently written C++20 reconstruction of five application registry callbacks and their value/handle helpers in `anadius64.dll` SHA-256 `9e420c3aae5ea26410f0bf578f86c47e51e36ff770b9e2a28b5eaee46aed786c`. Original preferred image base is `0x180000000`. It reuses the retained Ghidra pseudocode and assembly Evidence IDs recorded in `evidence.json`. No target binary was executed or changed.

`registry.cpp` is one production source object; `registry_tests.cpp` is one synthetic test group. Run `./build.ps1` from PowerShell with the retained workspace LLVM-MinGW toolchain. `validation.json` records the result and current source hashes.

## Recovered behavior

- `008980` / `008b80` look up a case-sensitive, explicit-length key in the host `Values` map. Missing keys yield empty strings. A present narrow value always selects the filesystem conversion path, even if empty. Wide values preserve UTF-16 code units and embedded NUL. `0086b0` / `0087f0` compare C strings through the required CRT case-insensitive comparison policy; null input returns 1 without consulting the map.
- Open callbacks `00f800` / `00f960` call the original operation first and then match `ClientKey`, `ClientKey2`, and conditionally `LanguageKey`. Root, options, and access are forwarded; they do not restrict matching. Matched failures call `010170`, allocate an opaque 4-byte fabricated handle, add it to the fabricated set, log, and replace the status with success. Both real and fabricated matched handles are tracked in the appropriate set.
- Query callbacks `00fac0` / `00fb60` snapshot the caller's byte capacity **before** the original operation. They then match tracked `ClientValue` or `LanguageValue`; the client path waits with `036880(-1)` before logging/resolving `ClientPath`. Client matching has precedence over language matching. Language access uses its already tracked set even if the language flag subsequently changes.
- `0091a0` / `0093a0` require the size pointer (otherwise status 234), restore the captured capacity before conversion, write the required byte size including NUL, support size-only queries, and copy only if capacity is sufficient. Narrow copies receive a byte count; wide copies receive a UTF-16 character count while the size output remains bytes. Secure-copy failure maps to 234. Explicit string length determines required size; C-string copy stops at the first NUL. A matched query changes type 0 to 1 even if copying returns 234; a nonzero type from the original call remains unchanged. An unmatched fabricated handle returns 2, retaining original operation output changes.
- Close callback `00f5b0` erases/frees fabricated handles without calling the original close. A real close failure retains both tracking sets. A successful real or fabricated close removes client and language tracking. Free/log failures stop subsequent normal cleanup; no invented recovery or success fallback is installed.

## API and unresolved boundaries

`StateRefs` binds host `Values`, three handle sets, and the actual `uint8_t` configuration flag. `Effects` requires real original callback forwarding, CRT comparison/copy, allocation/free, logging, filesystem conversion, and the existing execution wait. `ValueEffects` and the shared public helper functions can also serve the process/folder callback module. No default implementation performs real registry operations or installs a hook.

`abi_cells.hpp` is a new C++ ABI-storage bridge, not a recovered original class. `OpenA/W::result` uses `HandleCell` (8 bytes); `QueryA/W::type` and `size`, and both value writers, use `DwordCell` (4 bytes). An exact `Handle*` / `uint32_t*` or null converts implicitly for existing source callers. Native callers construct `HandleCell::from_raw(PHKEY)` and `DwordCell::from_raw(PDWORD)`. On the selected Windows x64 SDK, `DWORD` and `uint32_t` are distinct C++ types, while `HKEY` is a pointer: equal widths do not permit accessing these objects through `uint32_t*` or `uint64_t*` aliases. Each explicit `load()` / `store()` copies the complete scalar representation with `memcpy`. The cell never owns, initializes, caches, or mirrors the caller's bytes, and each store is immediately observable. `raw()` retains the original address so native forwarding can restore the actual SDK pointer type without replacing the caller's output storage. No implicit conversion to a scalar pointer is provided.

Cell storage must remain alive and provide the required 4 or 8 accessible bytes for each operation. The cell itself supports unaligned byte storage. Native API calls retain their own SDK storage/alignment requirements. Null cells can be tested and forwarded without access; direct null `load()` / `store()` raise `logic_error` as a new bridge-domain guard. This is not a claim about the original DLL's invalid-pointer exception behavior. Production code uses an explicit scalar load for the pre-original capacity snapshot and rereads caller storage at each original read; it does not retain a lazy proxy. Original-call writes remain visible on subsequent failure or exception paths.

Caller-supplied buffers must have the actual capacity represented by the incoming byte count and valid alignment for wide copies. Matched open paths dereference their result pointer in the original; this reconstruction raises `OutOfEvidenceInput` for null instead of causing an access violation. Inputs/outputs that alias or callbacks that mutate `Values` while a lookup/conversion uses it require separate ABI/lifetime evidence. Opaque fabricated allocation must satisfy the selected CRT's non-null allocation/throw contract.

The three `std::set` containers reproduce handle membership, insertion, and erase semantics, including duplicates, but do not reproduce original MSVC red-black node allocation layout, allocation failure side effects, iterator ABI, maximum-node overflow paths, or allocator metadata. Temporary `std::string` / `std::u16string` ownership likewise differs from original SSO allocation. Original static CRT locale state, `_stricmp`/`_wcsicmp` behavior outside the selected implementation, invalid-parameter policy, exception ABI, hook trampolines, loader wiring, concurrency, and full runtime equivalence remain open. Test comparisons/conversion use an explicit synthetic ASCII policy; the production code requires an implementation and makes no ASCII-only claim.

The module's 991 checks cover A/W paths, real/fabricated and duplicate membership, failure statuses, null inputs and outputs, key case behavior, original-before-override order, pre-original size snapshot, insufficient/exact/large buffers, size-only and missing-size paths, type preservation, secure-copy failure, embedded NUL, and conversion-side effects. Added storage checks use actual SDK `DWORD` / `HKEY` objects, preserved addresses, null and unaligned cells, explicit value snapshots, immediate same-storage visibility, and native-backed synthetic open/query paths including original-output retention after failure/throw. Scalar-cell alias visibility is tested independently; this does not establish original callback behavior for overlapping argument buffers or mutation of active `Values` storage. The tests make no Win32 registry calls and do not access user credentials, real profile state, original DLL/game, or online provider.
