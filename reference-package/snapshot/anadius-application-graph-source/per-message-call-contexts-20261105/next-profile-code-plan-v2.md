## Smallest coherent next production group: Profile header and implementation

1. Select behavior from the already immutable `Parent.operation_policy()`; default Serialized retains its current API and exclusion rules. Do not enable Concurrent in server/Graph/entry composition in this checkpoint.
2. Introduce private stable Job/Slot record types usable by both Impl and the handoff state, or an equivalent privately typed proof; no public token replacement, void-pointer registry, ambient current-job variable or TLS authority. Existing deques can remain original-worker-owned containers.
3. On the original worker, `prepare_job` reserves that exact Job under State.gate **before** allocating the handoff/offer. Capture the stable Job*, Slot*, closure*, SessionOwner*, observer/control*, native Logic* and JobLogic*, exact token generations and immutable entry/owner values. Capture ports/policy identities from the sealed root. Validate actual Parent control ownership outside the metadata gate, then recheck captured metadata before publication. Do not make native JobLogic mandatory for legacy inspection/unprocessed handoff APIs; typed processing eligibility is checked before entering Processing.
4. Keep `binding`/a stack same-actor preparation reservation published across handoff allocation, Parent offer preparation and request relinquish. Adopt a successfully returned offer into its exact row before callback-bearing postchecks. Retain the source strong owner, closure and row on unknown outcomes. Normal metadata allocation failure before an offer exists releases only the known preparation reservation.
5. A handoff is published before launch, but child eligibility still requires actual start-return and detach publication. The child uses only the captured record pointers, never `jobs/slots.size()`, indexing, iterators or `closures[...]`. Its metadata validation rechecks that those exact records still have the captured generations, live phases, strong/control, handoff identity, start/detach state and Slot logic. Immutable closure owner/function fields may be checked; request/response bytes belong to this job and are not inspected by siblings.
6. After `Parent.enter(JobMemory)` mints the exact permit, reserve one call against the handoff's own Fresh state and the captured Slot/Job under short metadata transactions. Maintain aggregate State.active_calls and a per-Slot call count only as observation/retirement metadata. Concurrent permission is the caller's live record plus permit, not aggregate count==1; no Slot-wide processing lock. Preserve the per-handoff busy/Processing exclusion for duplicate execution of the **same job**.
7. The retained checkpoint captures the stable handoff/dispatch tombstone and copied permit. It checks permit and Parent/source admission outside Profile locks, then exact record membership/generation under State.gate. It must not reject an unrelated original-worker Mutation merely because that transient flag is set, or infer failure from another healthy NativeProfile invocation. Use `failed_prefix()` in Concurrent admission/postcheck, while the caller's normal `process_native_job` return proves retirement of its own invocation. Serialized retains existing broad retained-prefix semantics.

Keep the existing child order:033d70 → exact current-thread exit-wait cleanup → track/no-op ownership bookkeeping → request snapshot → Prepared publication → end Parent Operation → `return_memory` → receipt. Publish the post-033d70 request header and message state only under the handoff's exclusive call; original completion may read them only after Returned. 9. Root greeting, frame allocation/start/detach, job/session table growth and borrowed RegistryView remain original-worker operations. Growth prepares allocating replacement storage outside State.gate, publishes shared metadata under it, and destroys old buffers outside it. Children only use stable prelaunch pointers, so they neither observe transient deque internals nor require a union catalog. New growth does not mutate existing published Slot/Job payloads. Original scans take/revalidate short protected record snapshots; no iterator crosses a callback and no concurrent child traverses a container.
10. Convert writes read by child validation—Job phase/generation/handoff/binding/strong/start/detach, Slot phase/generation/jobs/logic and per-Slot calls—to the same State.gate protocol. Root-only payload/context fields need no invented whole-request lock. Never run provider/checkpoint, allocator, JobMemory destruction, logic/control deleter or weak/strong final release under that gate. Decide error flags under lock and construct exceptions after unlock; preserve LastError around metadata only. Avoid simultaneous State/handoff/dispatch locks by snapshot/recheck rather than an opaque nested-lock chain.
11. Replace global active-call rejection in Concurrent Mutation with an original-worker mutation reservation that excludes reentry by that actor, not healthy child records. A particular Slot may retire only with its own jobs/calls absent and the actual native strong count zero; mark Retiring and detach its public binding rows under metadata before running environment/Logic/control cleanup outside. A different Slot's call is not a retirement failure. Global close/drain observes active records and returns not-quiescent for healthy live work rather than poisoning it. Snapshots continue reporting all active records.
12. `after_completion` captures the original-only count/eligible handoff pointer and generation under metadata, then calls completion outside it and reacquires/revalidates for the next record. Children must never use this scan or the global original-only `completing` context. `complete_job`, closure free, Slot.jobs decrement and strong release remain the existing original-worker response/021770 continuation. Synchronize their shared metadata and use captured records, but **do not move response scheduling, queue mutation, closure free or strong drop to the child in this Profile checkpoint**.

## Meaningful bounded fixture and remaining integration

Use actual PreparedMemory and NativeThreads, one warmed plaintext Session/Graph Logic, two real offered handoffs whose closures originate in frame/start publication. A reaches the actual supported UnknownMessage diagnostic and is held in its injected dialog; B uses the same Logic's actual GetConfig route, reaches Prepared and returns its memory while A remains held. The original worker must be able to inspect aggregate active work, prepare another job/grow the initial one-row job registry, and complete/reap B without waiting for A. Include stale/foreign identity denial and an isolated unknown provider prefix without clearing the held owner's state. Keep existing Serialized cases unchanged.
