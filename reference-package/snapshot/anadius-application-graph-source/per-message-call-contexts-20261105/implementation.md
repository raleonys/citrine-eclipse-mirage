# Graph per-message assembly checkpoint

Source only, 2026-11-05. Five actual changed files: Graph header/implementation and NativeMessage event header (three production), Graph integration fixture and NativeMessage fixture (two test sources). The before manifest also snapshots graph_tests.cpp, which remains unchanged and receives no changed-file credit. No compile, project tests, link, DLL execution or ZIP update.

Graph now publishes an exact actor/Logic/session/output/request admission before allocations, then a stable registered MessageCall. The registry keeps that call published through provider view close, local Dependencies and writer retirement, callback-target destruction and final admission. Each call has private Router adapters, opaque/checkpoint state, writer inventory, random/time adapters and native lock bookkeeping. The actual Parent, already-bound Strings/lease, configuration/Runtime/Online/authentication roots, queue and true event/achievement mutexes are shared. There is no per-message Parent binding or Root-to-Call-to-Root shared_ptr cycle: the registered call has a raw Root backlink, while actual Logic/local pins retain Root.

The new route builds one immutable application_io::CallContext from the actual child permit and obtains the three concrete provider views through their factories. Explicit NativeProfile Dependencies reference these adapters and the exact call lifetime. It does not swap the default provider bundle or infer an ambient job. Root metadata observations and unrelated Logic creation/retirement remain separate from healthy child execution; whole lifecycle drain returns false while calls/admissions remain. Pending and published calls both retain their exact Logic.

The original event pre-lock peek requires a single shared lock-free relaxed count cell. Structural map, payload and offset reads occur after the actual event lock. Post-lock zero is a legal no-pop path. Pop count/offset changes remain committed before unlock, including an unknown unlock result. Lazy initialization can take the real lock; an initialized ordinary peek adds no preliminary lock. Snapshot uses a shared passive atomic observation of the actual logical event lock; it grants no access authority.

Event insertion publishes a new payload only after Strings relinquishes the producer's own temporary ticket view. SDK and foreign pins remain. This is an exact last-use handoff, not delayed cleanup or a new wait. Independent review found and corrected missing shared-field reference declarations, root-only lock snapshot observation, pending-call Logic retention and this producer view transfer.
