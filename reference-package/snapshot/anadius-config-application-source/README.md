# Config2 büyüme ve koleksiyon uygulama akışı

Bu modül `019ad0` normal akışını gerçek dosya okuyucusu, parser, yeni kapasite/hash-list modeli ve mevcut ayar yardımcılarıyla birleştirir. Önceki `anadius-config-pipeline-source` sekiz anahtar/scalar sınırındaki tarihsel teslim olarak korunur; bu yeni giriş o sınırları kaldırır. CRT üretim kaynakları değiştirilmez.

Yeni giriş açıkça `config_application::load_and_apply` olarak çağrılır. Mevcut `configuration::initialize_configuration` ve diğer eski çağıranlar bu teslimde otomatik olarak bu girişe çevrilmedi; bütün startup/global grafiğinin bağlantısı hâlâ ayrı iştir. Normal Config2 yükleme/uygulama yolu testlidir; bu sonuç tüm başlangıç zincirinin yükseltildiği anlamına gelmez.

`load_and_apply(state, override, dependencies, files)` dosya adını filesystem codepage sınırıyla genişletir, executable parent ile birleştirir, gerçek `03b3f0` kaynağıyla ham byte okur ve yeni parser state kullanır. Tek BOM işlemi parser'dadır. Yalnız Config2 ilk kopyası seçilir; parser ve input depoları log çağrısından önce yok edilir. Yeni giriş `Dependencies::load_document` metodunu kullanmaz; diğer path/encoding/log/locale/OS/lisans/persistence sınırları zorunlu ve caller tarafından sağlanır. Kayıtlar sahip olunan C++ değerleridir; kullanıcı CFG/token içeriği veya özgün kod kullanılmaz.

`apply_config2` gerçek zaman sırasıyla Game → Emulator → User → Content → Entitlements → Achievements kopyalarını aynı `section` destination'ına yapar. Eksik alan lookup'ları mevcut noktalarında default kayıt ekler ve gerekirse tabloyu büyütür. Destination kayıtları anahtara göre değil eski dolaşım konumuna göre yeniden kullanılır; alt tablo kapasiteleri bu yolla sonraki bölümlere taşınabilir. Content/Entitlements record kopyaları ayrı bir `record` destination'ını yeniden kullanır. AchievementIDs lookup'u AchievementsSet'ten önce yapılır. Koleksiyonlar son kopya aşamasının gerçek mantıksal list sırasıyla gezilir; std::map/unordered_map dolaşımı kaynak yerine kullanılmaz.

Override User sonrasında döner; dolu koleksiyonlar kabul edilir ve atlanır. Base koleksiyonları vektörlere ekler. Scalar helper/OS sınırlarıyla lookup'lar iç içe yürütülür; erken hata, gelecekteki bölüm kopyalarını ve atamaları çalıştırmaz. Önceden hesaplanan bir sıra planına bağlı kalınmaz: callback daha sonraki koşulun kullandığı state'i değiştirirse yeni state gözlenir. Girdi/parser/read hataları log/apply öncesi; scalar dönüşüm hataları log sonrasında ve o ana kadarki değişiklikler korunarak yayılır.

`Trace` yalnız isteğe bağlı kaynak tanılamasıdır; bölüm kopyası anındaki kapasite ve sırayı kaydeder, özgün DLL özelliği değildir. Testler aynı iki Content anahtarının önceki Game kapasitesi64/128 ile farklı sırada gezilmesini ve önceki Entitlements kaydından kalan512bucket alt tablonun achievement conversion hatası öncesindeki kısmi güncellemeyi değiştirmesini doğrular. Böylece yalnız nihai değerler değil görünür hata sırası da kapsanır.

Doğrulama `build.ps1` ile C++20 / LLVM-MinGW / `-O2 -Wall -Wextra -Werror`. Testler memory stream ve yalnız kendi oluşturdukları `application-generated-fixture.cfg` dosyasını kullanır; diğer OS etkileri kontrollüdür. Ortak `../source-workspace/build.ps1` ve CMake tanımları vardır; CMake bu teslimde ayrıca çalıştırılmamıştır. Statik çağrı adresleri ve REA kimlikleri `consumer-audit.md/json`, kaynak/kanıt kayıtları `evidence.json`, bağımsız inceleme `review.md/json`, sonuçlar `validation.json` ve `common-validation.json` içindedir.

Kapsam normal, unique-key, load_factor1 container davranışıdır. Özgün MSVC layout/allocator ve native tahsis/exception/SEH zamanlaması eşdeğer değildir; trace allocation'ı da özgün davranış sayılmaz. Kaynak container'ın kendi alt ağacına alias olduğu copy atamaları ve eşzamanlı mutation bu uygulama akışında yoktur ve doğrulanmış sayılmaz. Path/locale sağlayıcılarının bütünü, license subsystem iç işlemi, tam global/native DLL kurulumu ve bütün DLL runtime eşitliği açık kalır. Bu aşama mevcut019ad0'ın eksik bağlantısını tamamlar; yeni benzersiz özgün yordam sayısını artırmaz.
