# Socket resolver boundary foundation

Implemented only the eight assigned socket receive/frame/write/container files. Final and captured-before SHA256 values are in `socket-resolver-source-hashes.json`. No tests were edited or executed; no compile/link, process/DLL execution, new REA query, original access, status or package change was performed. The twelve fresh parallel-frame records motivate the later actor integration; these new HOST projection interfaces are not additional recovered native functions.

The common `MemoryLookup` enum distinguishes Miss, Found and Ambiguous. ReceiveBufferResolver supplies exact bytes; AllocationHeaderResolver supplies the base for an exact data-8 header by value; DequeMapResolver supplies exact pointer-map windows/address identities. Their methods use copied output descriptors, changed only for Found. Owner admission may throw; lookup does not perform an SDK/application callback, free or invalid-parameter effect. Actual payload ownership/pins remain the owner's responsibility.

Optional resolver pointers are appended with null defaults to ReceiveBufferMemory, DequeMapMemory, WriteFinishContext and FrameReadContext. Existing aggregate argument prefixes and constructors keep their legacy bounded spans when the pointer is null. A nonnull resolver is authoritative: its Miss or Ambiguous never falls back to an old span. NativeProfile can later compose private inline windows with Parent using the pure lookup methods, without copying a mutable global catalog. A resolver pointer/result alone supplies no authority; consumers must compare it to the exact admitted owner or an explicitly bound composite before using that route.

Public pure helpers are `ReceiveBufferMemory::lookup_bytes`, `DequeMapMemory::lookup_map`/`lookup_address`, and `lookup_allocation_header(header, headers, resolver, base)`. Consuming view/address/header-free paths preserve the prior miss/ambiguity error texts. Existing null map identity still returns zero; malformed map byte count remains Miss in pure lookup and retains the original structural error in view. Legacy duplicate complete regions/header rows/map matches remain Ambiguous and leave the caller's output untouched.

Frame/write large-string destruction still caches capacity, adds39, resolves data-8, checks unsigned `data-base-8>31`, invokes invalid_parameter if needed, then frees with the existing address/byte count. The new resolver does not relocate alignment validation or synthesize cleanup. Normal free and logging/queue ordering are unchanged.

Remaining integration: Parent will implement and expose exact byte/header/map resolvers; selected consumers must wire authoritative identities, stable per-actor catalogs and real payload pins. NativeProfile still needs its private-window composite; Strings header publication/prune and Deques map catalogs still need explicit migration. Existing Serial catalog/span behavior must remain usable until that migration. No OriginalParallel selection, Graph/provider cloning or whole-handler unlocking is enabled by these eight files. Consistent rebuilding is required because aggregate sizes and polymorphic resolver interfaces are new; historical binaries/ZIP retain their previous proof.

Static before/current diff whitespace checks were clean. Compile/runtime validation awaits an explicit rebuild instruction; independent lower-Parent review will be recorded after its author freezes those files.
