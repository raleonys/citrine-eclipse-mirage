# Original concurrent actors — lower memory design review

2026-11-05. Read-only source architecture review following the twelve fresh native capture-site observations in this directory. This is a proposed coupled implementation plan, not implemented behavior or runtime validation. No production/test/status edit, compilation, tests, linking, target execution or package change occurred. The current recorded source checkpoint supplied by root is 71 pending files. Exact current inspected source hashes are recorded separately in `memory-design-source-hashes.json`.

## Decision

Use an immutable Parent operation policy, `Serialized` by default and `OriginalConcurrentActors` only in the explicitly selected Original composition. Keep explicit `enter()` / `enter(JobMemory&)` admission, but give each admitted operation its own stable actor record. Remove whole-body gates only after authoritative byte/header/map/IO lookup and upper invocation ownership are coherent. A metadata-only actor-count change is insufficient.

This addresses the native distinct-session trace: A remains in the supported UnknownMessage modal diagnostic, while warmed B can run GetConfig and send its response. It must also allow the original IOCP worker to accept/receive/fork/reap another row while A remains active. It is not a special unlock around MessageBoxW. Existing native event/achievement/socket-service locks still apply to the resources they actually protect.

The twelve-record `native-findings.md` / `native-evidence-index.json` plus `../handler-admission-overlap-20261105/caller-proof.md` establish the selected fork/receiver chain. The retained followup below also establishes the warmed plaintext same-session A/B case. A new server-wide or per-session strand/readiness barrier is not an acceptable substitute. This does not establish arbitrary simultaneous cipher/key mutation or unsynchronized foreign provider state as safe.

### Same-session extension is real, not a deferred permission question

025480 copies a completed frame into its own closure string, starts/detaches the job, consumes the shared input and rearms0280d0 without joining that job. Therefore B's second frame on the SAME accepted session may become a second independent closure while A is still in its diagnostic. 028d30 still invokes033d70 before response executor scheduling. Each invocation owns its local document/response/printer/string state; an executor used after that call cannot serialize the earlier call.

For an already-warmed valid plaintext session, retained033d70 reads+c4 at033de5 and skips decryption. B=GetConfig dispatches normally and reads+c4 again at034207; the zero branch at03457d appends NUL only to its local response. The+c4 stores at033ee1/033efb belong to bad-XML/error8 negotiation branches, not these two valid requests; there is no+c5 access in this path. A's UnknownMessage catch leaves through0345da rather than mutating the cipher/event queue. Existing show_lsx=false/warm-registry/empty-event qualifiers remove unrelated first-use/logging state; B's literal GetConfig needs no A-held data lock. This is a bounded valid same-session trace, not a claim that all encrypted/key-negotiation races have native synchronization.

Thus `Slot.processing` or `Logic::invocation_` cannot become a final Original per-session wait. The plan must use **per-message invocation records** keyed by exact JobIdentity/ActorRef, each with its own adapters, locals, DOM/printers/owned prefixes and retained failure record. Shared session owner/cipher remains the actual shared object; new source metadata cannot invent a native session strand. Root/original completion may serialize the later output-queue continuation where the selected scheduler actually does so.

## Proposed Parent contract

Names below are design signatures, not an approved final patch:

```cpp
enum class OperationPolicy { Serialized, OriginalConcurrentActors };
SessionMemoryDomain(Borrow&&, shared_ptr<LifecycleEffects>,
                    OperationPolicy = OperationPolicy::Serialized);
Operation enter();
Operation enter(PreparedMemory::JobMemory&);
ActorRef Operation::actor() const;       // exact admitted record, no new authority
JobPermit Operation::job_permit();       // same child record + parent identity
```

1. An actor record has stable storage, actual thread AND fiber, captured Domain/FLS index/PTD, Root-or-exact-JobScope identity, active/generation, its own mutation/construction/reentry state, and exact range-view borrows. The record remains as an inactive tombstone while any copied permit exists. Do not reuse its generation or clear another actor's record on scope exit.
2. Prepare potentially allocating actor/list/seal metadata outside the Parent metadata gate. Validate actual Borrow/JobScope/PTD outside that gate, then recheck membership/phase and publish with nonthrowing operations. Nested allocation-handler entry must not overwrite or acquire an existing same-actor operation. Revalidate after allocation; do not hold a metadata gate across an allocator or injected callback.
3. Serialized mode preserves present one-operation behavior. Concurrent mode permits one original Root operation plus independent exact child records. Reentry on the same admitted actor remains distinguishable from another actor. Keep source-algorithm reentry reservations per actor or per actual object, not a shared global `mutating` flag that poisons an unrelated healthy actor.
4. `JobPermit::check(parent)` proves the same live record, exact Parent, current actual thread/fiber, captured PTD and exact still-pinned JobScope. It must not require total actor count equal to one. Ending B's operation invalidates B's seal only; A's seal remains valid. JobScope stays pinned through the full native call.
5. Explicit upper `Invocation` retains ActorRef/JobPermit. For legacy no-argument virtual allocator/free/disposal APIs, a short metadata lookup may resolve ONLY an already admitted exact thread+fiber record. This is not ambient TLS admission: no record is minted because FLS happens to contain a PTD, and FLS is only a revalidation of the captured proof. This compatibility seam avoids replacing every virtual strong/weak release signature or storing a stack actor context inside a control that outlives it.
6. Do not hold a gate across handler execution, dialogs, logging, Online SDK calls, allocator/new-handler calls, socket lifecycle callbacks or OS handle wait/close. Copy the exact record/ticket reservation under a short gate, call the effect outside, then validate its completed prefix and commit under the gate. Preserve thread-local LastError around additional C++ metadata work, not around source-observable SDK effects.

## Exact catalog and storage lifetime contract

**Do not pin a snapshot of all live allocations for each Operation.** Modal A would then retain unrelated B storage and make B's free/reuse depend on dismissing A. The design uses exact requested-resource lookup.

- Append an optional typed owner resolver to `ReceiveBufferMemory`, keeping the existing aggregate `regions` fallback for Serialized/standalone fixtures. In selected Original mode, `view(address,count)` asks the resolver to find exactly one Live stable Ticket under the Parent gate, copies the bounded range, and records an exact borrow in the requesting actor before returning it. The persistent ReceiveBufferMemory/ReceiveBufferContext object itself can remain stateless and stable, so existing long-lived frame/disposal references do not point at a dead Operation.
- The actor's view borrow retains that raw ticket through the relevant source use; it is not just a pointer into a replaceable metadata vector. Explicit free first rejects real SDK or other live actor borrows and consumes the freeing actor's own stale views of that ticket. It then follows the existing immediate typed-destroy/unmap/native-free sequence. **Do not defer HeapFree until Operation exit**, move it to another actor, or claim a span remains usable after that actor explicitly frees it. Known physical failure retains its own ticket; unknown completion poisons and retains the prefix without replay.
- Actual session strong references, per-job closure/request/response ownership, and pending IO buffer pins remain mandatory. A resolver does not make simultaneous writes to one string/deque/cipher safe. Higher layers must hand a call its actual resource ownership; adding only catalog pins cannot authorize a foreign same-session mutation.
- Replace selected `Strings::prune()` whole `.regions` iteration with an exact contains/header lookup. Add an optional allocation-header resolver at the ends of FrameReadContext/WriteFinishContext: read exact data-8 from Parent-owned mapped bytes and return the base by value. Keep existing alignment/header checks. This removes the shared mutable header ledger from the selected live lookup path; it does not infer allocator provenance from an arbitrary raw pointer.
- `anadius-native-profile-source/native.cpp:39–47` currently copies ALL upstream Parent regions into its Invocation vector on each admit. Replace that with an invocation-owned composite resolver: private stable inline/local windows plus authoritative Parent exact lookup for owned heap/control windows. It must not copy or iterate a concurrently mutable Parent span. Overlay miss must be distinguishable from ambiguity; request/output/local inline windows must not be double-registered if already mapped. Event windows are refreshed under their actual event ownership, not by walking an unguarded shared map.
- Add an optional exact typed map resolver to DequeMapMemory (address_of/view). Deque Call stores a stable resolver identity, not Parent's borrowed maps vector. The map ticket borrow covers the pointer-array use. Queue mutation/growth reservation remains owned by that exact queue/call. A new map or retired old map must not alter another actor's cached span field.
- For IO, store OperationStorageBinding and DispatcherOperationBinding next to each stable Record/projection. Give PostedEnvironment/DispatcherState an optional owner resolver, appended for aggregate compatibility, and resolve one identity/OVERLAPPED under the IO gate. Keep generation/issuing/completion/loan ownership checks. Exact binding pointers no longer change during index-vector growth, so there is no concurrent external packet-field rewrite. Existing valid callback lifetime rule still applies: completion can destroy its operation and the dispatcher cannot access it afterward.
- Scan/grow index containers only under their owner metadata gate. Prepare vector/list metadata outside gates and commit/revalidate without callbacks. Return exact binding copies or an explicitly pinned record handle; never return an unguarded span that another actor can replace or erase during traversal. Adapters must not protect one full source operation merely by locking the whole IO registry across Parent/SDK work.

These additions are logical source projections, not native table layout, atomic ABI, fault equivalence or general foreign-memory safety claims.

## ApplicationMemory and PTD boundary

The existing application allocator can be reused; it is not necessary to give each session a different heap/domain. DomainStorage binds immutable native API/seed/heap state during initialization, and per-call MemoryEffects observes unknown native outcomes. Valid admitted workers already have distinct ready same-domain PTDs. Keep actual current PTD checks before and after lower effects and exact JobScope lifetime.

Parent's global `outstanding_allocations()==before` rollback criterion must go. A per-attempt reservation captures whether a raw pointer returned, before any later publication/check can throw. ApplicationMemory already erases a healthy no-allocation failure and globally poisons an unknown pending/returned native outcome. Thus a healthy unreturned Parent attempt may erase its own Reserved ticket after its own actor proof and backing state checks; it must not inspect whether some unrelated actor allocated in the meantime. A returned raw pointer or unknown native outcome is retained with the right ticket even when post-effect PTD validation fails. No speculative free of an unknown allocation follows.

Move ApplicationMemory's extra ticket-node allocation outside its mutex and splice after phase recheck; free already reserves the exact pointer's busy flag and calls the native heap outside that mutex. Cross-actor snapshots must not read partially committed per-attempt raw pointers without the owner gate. Do not hold the Parent gate while acquiring backing/Prepared gates; copy/check/revalidate in a consistent sequence.

The old header says shared fallback/OOM concurrency is not established. This change must not silently relabel all fallback code concurrent. Normal OOM on a valid ready actor writes its own PTD errno and invokes the selected native new-handler path after handler-lock release. Do not introduce an OOM-wide serialized body or reject legitimate OOM solely because a sibling is active. Missing/mutated PTD and arbitrary foreign handlers remain outside that proven valid actor state and retain unknown prefixes; arbitrary global errno-fallback concurrency is not claimed closed.

## Reap and close with active siblings

- Concurrent Parent `reap_jobs()` is still an original-worker maintenance API, outside an Operation on that same worker. It must not require that every other actor be idle or set a flag that rejects sibling allocation. Reserve only its maintenance transaction; let PreparedMemory snapshot Returned/Canceled rows, poll their physical handles with timeout0, and remove those rows after exact revalidation. Active Borrowed jobs and their JobScopes remain registered.
- NativeJobs must remove source_gate from child acquire/body/return and from reaping. Its own short gate protects row stage, receipt and pointer publication. Stable list rows already survive growth. A returned B row may be acknowledged/reaped/reused while modal A's Launched row stays live. Never wait on A as a prerequisite for B's ordinary response or new frame admission.
- `close()` keeps the existing actual conditions: no active actor/reservation, no live payload/partial construction, no provider/SDK/view borrowers, healthy backing and all prepared jobs logically returned/canceled. It reports false promptly while A is active and keeps Open admission, rather than taking a global lifecycle reservation and waiting for A. Retiring starts only after the zero-active commit; subsequent actor entry rejects.
- PreparedMemory final Borrow retirement/controller close retains its existing physical thread/FLS exit handling. This is the old final ownership condition, not a newly invented unload proof. A logical returned receipt is not an actual physical thread exit, and partial close/unknown handle prefixes cannot be replayed.

## Meaningful future validation source cases

These are proposed cases, not executed tests:

- Actual selected OriginalImage/NativeJobs two established sessions, warmed registry, plaintext/show_lsx=false. Inject the existing modal API lower to signal A entered the real UnknownMessage diagnostic and hold its return. B sends GetConfig on another connection; assert actual B response/receipt/physical row retirement before releasing A. Do not release A simply because a timeout fires and then call that a pass. The same fixture should admit another original-worker frame/fork while A stays held.
- Repeat with TWO frames on ONE established plaintext session: A unknown request held in its actual diagnostic and B GetConfig on the same connection, preserving different request IDs and distinct closure/result records. Assert B's correct response before releasing A. This catches a per-session hidden strand even when the distinct-session test passes.
- Warm capacity deliberately small, force Parent byte/map and IO packet/storage/index growth while A remains held; B's old live handles/buffer contents/packet addresses and A's request/permit remain valid. Exercise both allocation and free; accepting B but deferring all its cleanup until A exits would miss the defect.
- B Operation exits and invalidates only B's permit while A's still checks; stale, cross-Parent and foreign-thread/fiber permits reject. A known allocation failure must not poison merely because B allocates concurrently. Unknown allocation/free/PTD-change prefixes retain the exact attempt without replay or loss.
- Reap completed B while A remains Borrowed/active. Parent.close() returns false promptly, does not wait on A, and leaves A's valid operation intact. After ordinary A completion and physical exit, existing final close succeeds. Preserve Host Serialized behavior and existing isolation/unknown-outcome cases.
- Any real test of shared application data uses the actual native lock/domain for that data. B=GetConfig intentionally avoids needing A's diagnostic logging lease. Do not claim arbitrary foreign SDK/string buffers or simultaneous writes to a session are safe because this distinct-session trace succeeds.

## Remaining design boundary

This report provides the lower contract and dependencies; it does not authorize switching on concurrency before per-message Graph/Profile/provider ownership, live resolver consumers and real packet/response completion are integrated. Both bounded A/B counterexamples are confirmed source/native analysis. Arbitrary cipher/key mutation interleavings, foreign provider thread safety, unsupported CRT/fallback domains and native atomic/EH ABI are not implied by fixing those confirmed gaps.
