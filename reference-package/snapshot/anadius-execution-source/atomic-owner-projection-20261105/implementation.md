# Source owner projection over the same native SRW

The previous Graph-stage readonly audit identified plain owner_48 pre-lock reads racing another actual achievement owner's writes. This stage changes only live lock/unlock owner accesses to temporary lock-free relaxed atomic_ref loads/stores. Type, raw MutexState fields/size/offsets, SRW address, count reference, recursion rules, return3 rollback and error5/6 call sites remain. Initializer stays plain and explicitly requires pre-publication quiescence. No new body mutex, CAS/retry protocol, clone or global job/session strand is introduced.

Production candidate: execution.cpp SHA256 c9a30ba892a526b9b00068d7e8d15927a60e2ecf7eda8d23a02bbfa2576f6884; execution.hpp SHA256 eb6c3dd0fd279ee9aecafef33c60ba184ab424b3e003143b5271f91ce818ab55. The header documents the live borrower contract without changing raw layout. Static assertions require lock-free owner operations, compatible object alignment and exact owner field offset alignment. Helpers create and destroy atomic_ref within the load/store expression, so no reference survives into Acquire/ReleaseSRW or a foreign callback. This matters for WaitTarget's distinct private mutex, whose next owner performs its plain assignment only after acquiring actual SRW. Direct helper contenders use atomic owner access throughout their live lifetime; arbitrary overlapping raw field inspection remains unsupported.

Protected count is deliberately unchanged. Its selected uses occur after actual acquisition, during same-actor recursion or before actual release; Graph's signed reference escape remains within that same ownership. Worker/Graph raw idle validation is pre-publication. SourceGuard around Execution's existing wrapper is not extended to shared achievement operations. The actual production Parent/Profile/NativeJobs policy remains Serialized.

The independent SDK author supplies an actual shared-SRW two-actor test source using one controller and a Win32 child, with real platform forwarding and bounded synchronization. See test-implementation.md for its frozen exact source and assertions; authored source is not a passing run. No compiler, project tests, linker, executable, reconstructed/original DLL execution or ZIP operation ran. All original binaries and frozen build/delivery proofs stay unchanged. Profile/Policy, shared business/accept/packet/full child response ordering and actual NativeJobs route/policy integration remain separate pending work.
