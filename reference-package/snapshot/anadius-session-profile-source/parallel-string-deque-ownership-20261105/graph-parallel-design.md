## Concrete blockers

`graph.cpp:31–39,55–118,370–411` keeps one job/job_binding and global active/router_active/in_opaque flags. `JobCall::checking` is local to that singleton, but provider_actor/source/for_session infer the current message from the global weak job. Replacing only the weak pointer with a list would leave the implicit dispatch API and global flags unsafe. `writers` at31/39 and263–291/326 is also shared invocation ownership. Router itself is constructed locally at327–336, but its Information/Content/License/Event/Mutex adapters point back to those global flags and the singleton job.

NativeProfile `native.hpp:Dependencies/Logic` and `native.cpp:Invocation/process_native` retain one invocation_ and read Logic.deps_ throughout provider calls. A Graph wrapper must not temporarily overwrite deps_ around a call. It needs an additive process_native_call(parent,strings,out,request,Dependencies,checkpoint), with the supplied dependency set stored in that exact Invocation. The immutable constructor dependency set remains the default/greeting compatibility route. Same-session calls need independent invocation ownership, not one Logic clone/session strand; owner/cipher remains the actual shared SessionOwner. Active invocation membership must be distinguished from a retained failed prefix, so healthy A does not make B look like an unknown failure.

The concrete leaves also require a coupled change: Information effects.cpp14–67 has one job/busy/checking/checkpoint; Content effects.cpp19–80 additionally owns one GuardedFiles, guarded Clock/Formatter/Encoding and Persistence Engine; Licensing Core and Handlers each have one job/checkpoint/admission pair, guarded files and cross-installed handler/Core checks. Current with_job APIs publish an ambient synchronous job into each shared facade; running two such scopes against the same facade still rejects/poisons. A Graph context alone cannot fix them.

## Minimal explicit context direction

Introduce one owned message context containing exact Graph/session/Logic membership, Parent permit, actor identity, checkpoint/reentry state, per-call flags, raw writer inventory/proxies and private typed adapter objects. Its generated np::Dependencies owns/pins this context. All callbacks select their context through an explicit object reference, never a Graph current-job field, global/TLS lookup or temporary dependency swap. The Graph registry supplies lifecycle membership and source identity only; no metadata gate spans allocation, callbacks, dialogs, files or SDK effects. Unknown invocation prefixes keep their own context/backing and cannot clear a sibling's membership.

Add explicit provider scoped-facade factories (names to be finalized), returning the existing typed Effects/LicenseHandlers interfaces bound to that context. Facades own only invocation-local checking, XML/writer/file wrappers and guarded lower adapters. They retain references to the SAME provider/business root: Runtime/CallbackStateView, configuration containers, Paths, Online, authentication cell and shared AttemptState. Do not reconstruct Content/Licensing from a copied Runtime/configuration or copy attempted_files/blocked counters into independent sessions. A GuardedFiles per scoped facade can share the existing raw file Factory while retaining its own pending raw stream prefix; it need not change the common GuardedFiles implementation merely to avoid a shared busy field.

Build the Router inside the message context using current authoritative StateReferences and that context's scoped providers. Keep native achievement/event locks on the shared data they actually protect. Graph event/achievement lock bookkeeping must record the owning context/actual actor rather than treating another actor's legitimate lock as a global reentry violation. No new global message/session mutex or special unlock around the selected dialog is acceptable. Original lifecycle/configuration-replacement operations can reject live contexts to avoid invalidating held container references; ordinary original accept/dispatch/reap must not be rejected merely because a message context exists.
