## Priority and observed limit

Actual NativeJobs entry presently executes acquire → process_message → return_memory. It does not call Environment.enter_job/clone_environment or finish_environment_work. Therefore NativeJobs per-row execution/maintenance admission is the next directly selected concurrency task. Generic tracked Environment work is a real remaining reconstruction domain, but this plan is not a reason to postpone that directly selected task or enable Concurrent globally.

Environment's singleton weak job, job_binding and checking (`environment.cpp:65–123,370–424`) cannot represent simultaneous scopes. Global growing/releasing and active==depth (`:184–269`) also make an unrelated actor's work invalid while A allocates or consumes a work pin. Policy.finish_environment_work (`policy.cpp:249–312`) separately reserves environment_work_active, so removing only Environment.job would still reject a legitimate second tracked release. Replacing those flags with counters without exact caller/source membership is insufficient.

## Explicit actor execution, not an ambient job

The concurrent API should be an additive call-bound execution view owned by JobScope, constructed from immutable application_io::CallContext plus exact protected source address/capability/Origin. The scope registry owns stable state with raw/nonowning Control backlinks; the wrapper pins Control/code backing. It retains the actual Parent permit, source checkpoint backing contract and scope generation. Nonallocating admission precedes metadata allocation. Normal close retires private callback/adapters while registered and under the live context; unknown rows/calls remain registered with shared sticky health. Closed wrapper destruction is metadata-only.

**Do not select a scope by current thread/fiber, TLS/FLS or a replacement global weak job.** Those fields only validate an explicitly supplied context. Existing raw Root thunks remain root-authorized legacy adapters. Scoped operations receive their view explicitly; a query capability may carry lineage only when minted/validated by that exact view. Two scopes may borrow the same protected Initial source while owning independent derived rows. A job may not destroy its protected source or access another scope's temporaries just because Session/Origin matches.

A concrete seam is a narrow typed environment-operations adapter carried by the existing constructor/message/response contexts: query, move, copy, destroy, prepare40 and the measured factory58/20/88 calls. Null adapter preserves current provider dispatch. A scoped adapter binds CallContext + Control + scope id and routes the **same native algorithm call sites** to the shared row operations. It leaves published environment fields/root tables and actual family state singular. It must not manufacture a nonowning fake environment row or extra work retain simply to smuggle authority through table lookup.

This requires an explicit context seam because current 023dd0 directly invokes source.operations_10->query/destroy, and static factory callbacks receive only an opaque query; calling those unchanged Root callbacks from a child cannot recover a caller permit. Merely adding a scope list behind perform would recreate ambient authority. The first implementation must settle this typed API with the socket-context owner before editing, rather than add a disconnected helper or silently reinterpret a raw capability as permission.

## Row and effect transactions

Use stable per-effect records and exact source/destination row claims under Control.gate. Shared read/protected-source claims may coexist; exclusive move/destroy/output claims cover only the affected address+capability+generation. Reserve destination identity before any allocator/new-handler callback. A prepared row node is allocated outside the gate and spliced/committed after own context and exact source proof revalidate; stable list-owned rows avoid copying/republishing a global vector while another effect is active. Preserve the existing Serialized storage/behavior, or demonstrate equivalent legacy behavior before replacing it. No whole-ledger scan may borrow unrelated Parent payload tickets.

Put checking/preparing/retiring on the exact effect/scope, not Control. Own temporary-row counts and row capabilities replace aggregate active==depth permission. Snapshot.active_calls remains aggregate observation. Root session/accept and disjoint row operations can progress while a child is healthy; final close returns false for live scopes/effects, without closing their admission. Full-field source proof is rechecked after outside effects, never through a saved movable-vector Row reference.

Destroy claims exactly its row, marks ReleaseEntered before the capability, and retains that claim through the real work drop. A per-release Policy record owns exact Parent/scheduler/error-provider identity, original-actor proof or copied JobPermit, source checkpoint and precise consumed/failed state. It coexists with healthy sibling work and ordinary original Policy calls. The atomic decrement immediately publishes consumed=true before any later callback; old1 enters the existing02a190 sequence synchronously. Failure retains entered/consumed prefixes in both owner ledgers and cannot authorize a second decrement. Shared stop/wake fields remain shared and atomically/coherently updated; they are not per-call flags. Close/drain checks pending/release registries before retiring Ports or leases.

Runtime.EnvironmentWork/StopApi is already per-call stack state and confines raw access to the exact zero packet, selected scheduler and retained lower API. Its failed-post latch precedes callback-bearing admission. Audit its graph/Ports/code lifetime and final proof under concurrent calls; add no blanket raw API, new stop channel or defer-to-root behavior. Only change Runtime sources if that audit identifies a concrete lifetime/reservation gap.

Handler/response callbacks can consume a task and destroy its environment/operation. A future scoped scheduling path must release its row-use claim at the measured ownership handoff and never inspect the old row/task after the native callback. Current original-only handler/response restrictions cannot simply be removed: their Worker/dispatcher adapters and the child response tail require an explicit actor-Ports integration. This remains separate from projection/copy/release support, not a claim that this foundation reconstructs the full child tail.
