## Minimal coherent change if this target is selected

1. **Profile:** use stable indexed Job storage, preferably deque<Job>, and retain the separate contiguous closure-binding vector. Grow the binding vector and append Empty Job records before selecting a new Job reference. After all allocation/checkpoints, copy existing closure entries and publish the new `message.closures` span without an opaque gap; old metadata storage must remain alive until publication. Preserve every token generation and heap closure identity. Use an explicit local growth reservation/reentry check so an allocator callback cannot register a job into partly appended metadata. Allocation failure must leave old rows authoritative or follow existing sticky poison/unknown handling; no closure/strong pin may be replayed or discarded.

2. **NativeJobs:** the smallest pointer-stable shape is list<Row>, since no caller needs row-index lookup. When no Empty row exists, prepare a new Empty node in a separate list outside metadata gate, recheck existing begin/admit seals, then splice the node under gate and reserve it. `row.owner` must be initialized before any launch. Existing child Row* remains stable. Splice is nonallocating, and all container-structure publication stays under the same gate used by snapshot scans. Do not append a deque outside gate while snapshot may iterate it, or allocate list/deque storage while holding the nonrecursive metadata gate. A vector<unique_ptr<Row>> with prepared-table swap is another safe but more invasive indexed solution.

3. **PreparedMemory:** its shared JobState/list storage already gives stable addresses. The actual64 admission guard and the NativeJobs constructor's coupling to it must be revised together. Keep real per-job thread handles, scope pins, actor/PTD checks, logical return and physical reap unchanged. The existing prepare_job currently allocates shared state/list storage while holding a nonrecursive gate; a growth implementation should prepare an unpublished node outside gate, then revalidate the original worker/borrow phase and existing job_control reservation before a nonallocating splice. A failed prepublication preparation must not create an owned JobMemory whose destructor poisons an otherwise unpublished offer.

4. **InlineJobs, if included:** grow indexed storage before taking Row* for token.slot. Preserve generation/ticket/callable ownership and existing active/reentry seals. Stable deque rows or stable heap rows avoid retaining a Row* across another allocation-related code path. Do not silently substitute InlineJobs for the actual NativeJobs production selection.

5. **Validation scope for a later explicitly authorized rebuild:** pending Profile closures beyond64; the same pending native rows surviving additional launches; Parent offers beyond64; old-row receipt/detach/body/physical reaping after growth; exact spans and strong counts; allocation/reentry prefixes; generation reuse. Existing fixed-job exhaustion expectations would need targeted replacement, while duplicate/unknown launch/physical failure cases remain. No new test source was written in this audit.

This is a multi-layer target rather than a one-counter fix. Correctly growing only Profile records still encounters both NativeJobs and PreparedMemory limits. It can be deferred in favor of a bounded business-function target without changing the already corrected session-registry path. No new unload, CRT or lifecycle framework is required by the capacity change itself.
