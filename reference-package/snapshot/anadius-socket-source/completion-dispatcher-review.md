## Verified normal-body contracts

The implementation captures the native TLS slot identity once before the loop; uses gate CAS expected one to zero; detaches the scheduler queue only when its head is nonnull; preserves the shared actual CompletionScheduler head/tail and queued operation type; and reads live service links after callbacks in both separate service traversals. A failed post recursively enters/leaves the same gate, reconnects the failed operation and remaining live local chain to the live scheduler tail, restores the dispatch flag to one, and retains the outer gate until timer/direct cleanup processing ends. Failed queue publication does not invent last-error reads or cleanup.

Timer processing receives the previous signed accumulator directly rather than adding an invented minimum. The helper uses unsigned 32-bit subtraction for NEG wrap, bit-casts to signed int32, sign-extends to int64, and only then multiplies by ten. SetWaitableTimer uses the live timer handle, period 300000, null callback/argument and false resume; its return is ignored.

Before GQCS, the three outputs are zero; SetLastError(0) precedes the live timeout field read; timeout min is unsigned; the port is read live. GetLastError is read immediately after the wait adapter, unconditionally, including success. The native adapter copies scalar outputs without calling mapping/category/provider callbacks before that read. It forwards all five SDK APIs through injected function pointers and performs no SDK call in its constructor.

The nonnull operation path consults the live epoch through the cached native TLS slot, uses signed guard comparison, reloads guard after its header provider, registers the opaque callback only at -1 and then invokes footer. The binding lookup is a pure borrowed span search after status caching/guard work. Its SDK pointer identity is captured while the operation is live at aggregate construction; later unrelated lookups compare the cached identity without recomputing a member address through an operation whose callback may have ended its lifetime. Rebinding requires updating both the operation and cached identity, binding storage must remain live, and a matching operation must still be live. Packet fields are explicitly separated from cancellation error storage; no original OVERLAPPED memory overlay or code identity is dereferenced. Key exactly two reads the bound packet error/byte fields without writing them. Other keys store static system category A1110, cached status and bytes. Metadata handling precedes queued CAS; the callback is invoked only for old state exactly one, whereas zero becomes one and retries. The temporary atomic_ref lifetime ends before a callback may delete the operation, and no operation/binding field is accessed afterward in that dispatch call.

After callback, pending count is tested as signed int32. A positive value is cleared before two required `024100` copy providers with distinct destinations and second source equal to first destination. The provider contract includes the native zero-pair/copy/return-destination behavior; it is not counted as a new recovery. `029880` is declared noreturn, matching its full CALL-rethrow/INT3 listing. No normal pending-rethrow fallthrough into the guard block was invented. The other branch writes logical generic success before work-count fetch-sub and calls actual recovered stop only for old count one, then returns one.

Failed null-operation waits distinguish infinite original timeout retry from finite timeout generic return zero. All other cached errors call system category even for zero. Successful key-one wake packets retry without exchanges. Other keys clear low32 wake, read low32 stop via required atomic effect, retry on stop zero, otherwise exchange wake to one; only previous zero posts a relay on the live port. Relay failure caches a new last error before category lookup; all relay exits return zero. No flag rollback or work decrement was added. The native R15 overwrite has no further normal read, because this branch always exits.
