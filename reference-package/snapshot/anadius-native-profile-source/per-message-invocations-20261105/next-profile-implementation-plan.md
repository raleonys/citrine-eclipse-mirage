# Exact next Profile implementation map (read-only)

2026-11-05. Additive, unreferenced plan after the101-pending checkpoint. No production edit, build, tests, linker, DLL execution or REA query. Frozen evidence/reports are unchanged. Parent policy remains the only mode selector; actual production stays Serialized.

## Chosen storage and authority model

Keep public SessionToken, JobToken, JobIdentity, JobHandoff and both Jobs interfaces unchanged. Keep the existing stable `deque<Slot>` / `deque<Job>` storage; do not replace the business/session objects. Add a source-private typed `JobHandoffState::Capture` containing the exact Application, Job* and Slot* plus their captured generations/identity. Allocate it while preparing a handoff BEFORE offering memory or launching a child. A small `friend struct JobHandoffState` declaration/out-of-line Capture destructor arrangement in profile.hpp permits the private typed references without publishing a new token API.

Every child method uses that capture after pinning DispatchState. It must never read `jobs.size()`, `slots.size()`, index either deque, or iterate them. This is essential: Root deque append can allocate outside the metadata gate while old objects remain stable; merely putting a mutex around child indexing would still race that append. Captured old rows cannot be popped by growth rollback, which removes only unpublished appended rows. Existing closure-binding arrays may still be checked under the State gate: their old published prefix remains alive throughout preparation and replacement commits under that gate.

Keep each claim's busy/message/offer state and exact Parent JobPermit as its authority. Use a small per-method ChildUse RAII reservation on that captured claim/Slot, not one global current job. `Message::Processing` protects one message; it is not a Slot processing flag.

## Fields and lock discipline

Add immutable bound Concurrent mode; aggregate child-use and Root-effect counts; per-Slot child-use/greeting-retirement observations; and an Original-only growing_sessions reservation alongside growing_jobs. Keep total active_calls for Snapshot/drain. In Concurrent mode current mutation becomes Root-only reentry metadata, rather than a reason to reject every healthy child. profile_call remains binding/whole-application lifecycle metadata, not a Session-wide admission gate.

Do not nest DispatchState, JobHandoffState, Profile State, Parent, Policy or provider gates. Order is sequential: pin dispatch and release its gate; reserve/check claim and release its gate; enter/check exact Parent; capture/revalidate State metadata and release its gate; invoke checkpoint/provider. A checkpoint checks its own claim, permit and captured row twice around opaque work. Exception text, allocation, target destruction, native refcount disposal and provider calls occur outside State.gate. Atomics/trivial field publication may commit inside it.

Raw Slot/Job references remain valid only while the exact claim/Root reservation protects their generation and retirement. `RegistryView`, ports(), session() and shared frame/read/write/message tables remain original-worker borrowed APIs. They do not become child catalogs. This keeps the change within Profile.hpp/.cpp and avoids a new factory/actor framework.

## Required Policy companion

The existing `cleanup_job_exit_waits(permit, checkpoint)` signature is sufficient. Its implementation must stop borrowing Policy's global active flag: use an exact child cleanup reservation and aggregate child-cleanup count, with the same Parent/permit/lease/current-thread proof and independent checkpoint. Its validate path must not call global `valid()` (which requires Root active) or toggle Root `leave()/failed()` state. Metadata phase/source checks and own reservation replace that dependency. Retire the checkpoint outside gates before ending only that reservation. Underlying ExitWaitRegistry already selects the actual current thread under its narrow registry lock; do not rewrite CRT or clone it. Policy close observes outstanding child cleanup without poisoning healthy work.

## Deliberately still disabled

NativeProfile's new per-call Dependencies API is ready, but Graph still has one current job/router/writer state and its provider facades need explicit call views. NativeJobs still holds source_gate across acquire/process/return and reaping. Those must be integrated before production selects Concurrent. The existing HOST split is033d70 on a child followed by the response/021770 continuation on Root; this plan does not assert full native child ordering. Child clone/environment scheduling and OwnedAccept's body-wide gate remain their own explicit coupled prerequisites.

Unknown processing keeps that claim's request/response/closure/native strong and adopted providers retained. No033d70 replay, guessed rollback, counterfeit completion or clearing another claim's poison is permitted. The later same-session warmed plaintext A-UnknownMessage-modal/B-GetConfig fixture must show B's real response before releasing A, then ordinary return/receipt/FLS/reap, without a Session strand or manual counters.
