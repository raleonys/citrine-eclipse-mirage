# Next Graph assembly plan — read-only, unreferenced

This is a new planning artifact, not an amendment to the recorded NativeProfile proof. No source, build, test, executable, DLL, ZIP or native-analysis session was changed/run.

## Current boundary

NativeProfile now exposes `process_native_call(...,const Dependencies&,checkpoint)`, `failed_prefix()` and `active_calls()`. Its frozen source hashes are native.hpp `ca43abd9f9fe72250f9ad60dc435603c5df2b79c3ad4a7a8971d62e53e425239` and native.cpp `ae98f0527ddf2f50d61223d182834e0a4ea2e591f0447963cb808be7f60d2535`. Graph is still graph.hpp `de539b9a711a527a824ff55d9b22ac67c6098fb3657ab3d0ee49bc0c0d853aaa`, graph.cpp `fc90cf952eb5bb9230421d8dc97981ed6c7b60cf94d5b18f0cbd695ea0fdaf84`.

Graph.cpp 31–118 selects a singleton weak `job`, `job_binding`, global active/router/opaque state and current-job inference. Its adapters at 217–367 use that same state; writers are retained globally. `process_job` at 370 onward rejects any active job and `logic.retained_prefix()`, then calls the default-dependency API. Thus merely allowing a second NativeProfile invocation cannot make the actual Graph route concurrent. Concrete Information, Content and Licensing separately retain singleton job/checkpoint/busy state; continuing to call their existing `with_job` on one facade would still reject the second actor.

## Explicit message owner and API

Keep the public Graph lifecycle surface small. Replace private JobCall with a stable, registered `MessageCall` holding Graph backing/lease; exact Parent and Strings; SessionView, Logic and control; copied exact JobPermit; actor thread/fiber; supplied output/request identities; its own checkpoint, checking/active/router/opaque flags, phase and writer inventory. Reserve a pending descriptor before compiler allocation/target copies, publish only coherent ownership, and retain the failed call's actual providers/objects on unknown failure. One call's end removes only its descriptor. No Graph metadata lock spans an allocator, checkpoint, provider, SDK or provider destruction.

Every provider adapter receives `MessageCall&` or a stable shared reference explicitly. `call.admit()` validates the same graph phase/Parent/session row/control and exact permit, then invokes only its own checkpoint with its own reentry marker. Effects, Events, Clock/Random, Information, Content, Licensing, Writer/Xml proxies and Router are call-owned views. Construct `np::Dependencies` with lifetime backing for this owner and those exact adapters; invoke `logic.process_native_call`. Do not rewrite `Logic` defaults or search a global/TLS/current-thread job to recover context. `failed_prefix()` gates failed reuse; `active_calls()`/registry membership inform relevant retirement, while a sibling's healthy `retained_prefix()` is not a conflict.

The message's real Router continues to rebuild its spans/references from the SAME StateView roots. The actual Runtime/configuration, Paths, Online object, authoritative authentication cell and AttemptState remain shared originals. A local `handlers::Profile` remains the existing per-dispatch projection. Separate message storage is not a new Runtime or copied business state.

SourceReview's coordinated provider proposal is additive `make_call_view(const CallContext&)` (name/signature provisional). Use a small explicit immutable context containing Parent, copied exact permit, borrowed checkpoint and captured actor identity, created only within the actual admitted actor. Returned Information/Content/Licensing interfaces own execution/checking/busy, guarded file streams, Engine and clock/encoding adapters. Their immutable options/raw lower identities stay shared with the original provider. Owner registration must cover allocation and unknown-prefix lifetimes; original owner retirement requires registered views to retire. Legacy default/CheckedCalls/with_job contracts remain compatible for existing HOST callers.

Licensing needs one context shared by each call's Handlers AND nested Core, with the actual prebound AuthenticationCode and same shared AttemptState. Rebuild only handler execution adapters against those references. Do not install a call into Core's existing global `handler_context` or copy attempt/block cells. Content needs its own GuardedFiles and PersistenceEffects/Engine over the same configuration/Paths and raw Factory: its current single stream reservation must not serialize unrelated calls.

## Shared locks and original-worker operations

Keep the actual event queue, achievement data/mutex and shared log roots. Move lock ownership/recursion/mode and native-pop bookkeeping into the owning call, with shared mutexes protecting the actual shared data. Another actor must acquire the actual native/semantic lock rather than reject because a global `event_locked`/`achievement_locked` flag is set. Do not hold Graph metadata across lock waits. Preserve event growth/pop FIFO and the exact protected head. No event union catalog is needed: 009eb0 copies short inline source bytes directly (response_containers.cpp 25–29), while heap event bytes resolve through Parent. The four invocation-owned inline resolver regions remain appropriate for that copy path.

Install, initial mutex binding, whole-configuration replacement/update, authentication rebinding and final drain/close remain original-worker operations and can require no active messages when they invalidate roots. Original runtime accept/session creation, greeting, disjoint-row retirement and reap must progress while another message is active. Restrict Logic destruction only against that Logic's own active/failed invocations. Passive original-worker snapshot/retained/profile/policy/backend metadata must not keep the blanket `no_job()` rejection. Enqueue uses its explicit root admission plus the actual shared event lock, not another message's context. Final drain observes the whole call inventory before releasing shared queue/lease/business backing.

## Source groups and validation route

Minimal implementation groups: Graph cpp/hpp; Information effects cpp/hpp; Content effects cpp/hpp; Licensing effects cpp/hpp, plus one narrow shared context declaration in an already suitable header if needed. NativeProfile's new API needs no speculative rewrite. Alias separately reviews Profile's job/request/response ownership and exact runtime policy selection; those are prerequisites, not changes to infer from this plan. No OriginalConcurrentActors production enable is authorized by this document.

Reuse `graph_integration_tests.cpp`'s `prepared_native_profile`/`run_prepared_native` (580/498), actual NativeJobs/NativeThreads, `ConcreteProviders` (422), `NativeHooks` (438), real XML/Router and explicit backend imports. Add a separate bounded parallel mode, preserving ordinary 70-message sequential/delayed-exit/negative modes. A controlled concrete Licensing diagnostic/dialog can hold supported UnknownMessage A; deliver B only while A's actual call remains live, require real GetConfig long-id response/free and child physical reap BEFORE releasing A. Use finite events and synchronize test trace writes, not release-A-to-pass. The handoff test's `parallel_native_invocations()` is the already-authored lower lifetime/reference pattern, not a substitute for Graph coverage.

Then exercise per-provider isolation through the existing real native-body routes (GetProfile/GetAllGameInfo, GrantAchievement, GetAuthCode, QueryEntitlements), with a selected concrete lower callback held while a sibling actually uses the same provider root. An external fake Effects route or only A-licensing/B-GetConfig would not establish concurrent Content/Information isolation. The current receive fixture feeds one request per completion and asserts one sequence, so parallel input delivery must be a separate bounded mode coordinated with actual Profile splitting/job retirement. Preserve response FIFO/source pins and physical FLS/reap checks; do not assume those upper layers already permit overlap. All proposed regressions remain unexecuted until an explicit rebuild request.
