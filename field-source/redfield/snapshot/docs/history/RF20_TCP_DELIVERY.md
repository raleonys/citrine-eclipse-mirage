# REDFIELD RF20 — TCP-owned Grant delivery

FrameObserver has exactly one received/respond/prepare callback. Existing byte-only observers retain their output-array contract. The new prepare callback can fill that same bounded output array or return an owned FrameDelivery, exclusively. Null delivery and zero bytes means no response. Owned response must be nonempty and both response/event lengths must be below16 KiB. A delivery's immutable views remain valid until destruction. Commit is noexcept and called exactly once at full successful response write completion.

The peer holds one unique_ptr and one event-phase flag. Its delivery object is also the bounded, pre-reserved event slot: both messages have been validated/admitted/allocated before the first write. There is no growing queue, response copy, watcher snapshot or socket-global transaction singleton. Chunks remain at most4096 bytes. The peer stops reading while sending. After response completion, commit publishes the candidate without allocation; an event, if present, then occupies the send phase before any buffered next request. Responses and events have separate counters; bytes_written counts both. committed_deliveries counts successful FrameDelivery commits, not remote acknowledgements.

Error, zero write, timeout, stop or framing rejection before commit cancels the ticket. close_peer cancels/closes but retains the delivery while an async handler may still borrow its string buffer; reap destroys it only after pending=false and socket closure. No commit runs while stopping/closing. If the owner invalidates commit, the response may already have been written, but no event is sent and the peer closes. Full local TCP write is the explicit boundary, not proof that the remote application read or applied it. A cancellation before the completion callback may leave bytes at the remote while local state rolls back. No network exactly-once/atomicity claim is made.

After commit, event cancellation/failure cannot undo published state. There is no durable retry, cross-peer subscription, global watcher or fanout. One event is delivered only to the requesting plaintext connection on a count0→nonzero completion transition. Partial/repeated/no-op grants carry no event. Each message has the existing send timeout policy; event starts its own send phase. Stop drains pending completions before closing AchievementSession.

LocalService initializes its AchievementSession from the original immutable configuration after ServiceSession starts, then starts transport and publishes the port. Grant uses the existing exact RF19 selector/serializer and current_utc_timestamp helper. QueryAchievements pins the current committed snapshot; competing reads cannot observe an unpublished candidate. The original configuration publication and other config-backed routes remain unchanged. Busy competing Grant is a peer-local rejection; no scheduling fairness or wait queue is introduced. Context-free/config/Auth-only dispatch APIs retain no Grant binding.

RF20 changes existing project-owned transport/LocalService files and adds three behavior regressions. No adopted/derived body changes, new core TU, vendor change, hook or public export change. Native Windows and live SDK/game acceptance remain separate NOT_RUN evidence classes.
