Atomik tek dosya replace ve proses içi batch rollback aynı şey değildir. Batch elektrik kesilmesi/process kill karşısında bütün dosyaların aynı anda görünmesini garanti etmez; directory fsync, durable journal ve çok prosesli lock yoktur. Windows ReplaceFile/MoveFile/flush davranışı henüz native sınanmadı. TOCTOU/reparse yarışlarına karşı mutlak filesystem sandbox iddiası yoktur.

Yazım başarısızlığı ordinary rollback tamamlandığında önceki dosya/bellek/event halini korur. Rollback tamamlanamazsa uygulama fail-closed durur, sahipli preimage temporaries korunur; kullanıcı recovery incelemesi gerekir. Başka instance veya dış uygulama aynı dosyaya yazarsa transaction izolasyonu kanıtlanmış değildir.

Eski kökler otomatik temizlenmez. Debug log sınırında silme/rotation yapılmaz; mevcut oversize dosya olduğu gibi bırakılır. Custom avatar ve module sidecar asla üzerine yazılmaz. Provider indirdiği dosya yalnız o instance nonce dizininde sahiplenilir; mevcut genel cache silinmez.
