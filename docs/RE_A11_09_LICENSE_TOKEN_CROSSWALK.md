## Source comparison and already-owned evidence

**Token status, CBC and marker extraction.** Both current and donor `load_token_02afa0` call status with flags 3, allow error kinds 1/9, read only kind 2, attempt AES/CBC from byte 65 and ignore the decryption boolean. Both search *literal counted bytes* for the first `<GameToken>` at or after offset 65 and the next `</GameToken>`; this is not XML DOM parsing and does not entity-decode or stop at embedded NUL. Both explicitly throw `OutOfEvidenceInput` for short ciphertext lengths 1, 17, 33 and 49, outside the safe reconstructed original-memory domain. Existing [token tests](../tests/unit/token/token_tests.cpp) cover the exact boundaries and invalid padding. Open [#166](https://github.com/raleonys/citrine-eclipse-mirage/pull/166) adds a native Application/RequestLicense/token-retry case. **No duplicate test or unverified original-memory parity claim is warranted here.**

**License validation and retry ownership.** `RequestLicense` checks the configured DLL hash length, file status and actual hash before accepting a cached license. A signed persistent counter permits up to two normal/cached file attempts; exhausting attempts marks the blocked flag before reading both ticket attributes. `InvalidateLicense` clears only the in-memory license and does not reset the counter/block. Existing [license unit tests](../tests/unit/license/license_tests.cpp) cover the status matrix, ordering, error branches and ticket text. The native test in #166 exercises a different real-file path; neither validates arbitrary provider/game behavior.

**Online GetAuthCode — nonidentical owner design.** The donor license source adds optional `AuthenticationBinding` / `OwnedAuthEffects::copy_online_auth` and a single-bind-before-dispatch lifecycle. The accepted product does **not** have that extra donor-owned auth cell; it reads the caller-supplied `state_.auth_code_0a3b18` reference as fallback and immediately copies the valid provider-returned `const char*` before passing text to the XML printer. This is a **source-design difference, not a proven product defect**. PR [#186](https://github.com/raleonys/citrine-eclipse-mirage/pull/186) adds a focused regression for borrowed auth scratch overwritten during response output. PR [#111](https://github.com/raleonys/citrine-eclipse-mirage/pull/111) tests *profile getter* scratch reuse and is not proof of auth callback lifetime. Donor-owned provider interfaces must not be imported without a demonstrated current-product need and an owner-approved ABI/lifetime policy.

**KeyForLicense write policy.** Both selected sources construct a 65-byte prefix followed by counted XML text, encrypt the suffix from offset 65, leave an already-existing regular `.dlf` file intact, create the parent and ignore the plain binary-writer boolean result. This is separate from the checked atomic achievement XML/INI policy; copying donor assumptions into achievement persistence would regress a product decision. PR [#163](https://github.com/raleonys/citrine-eclipse-mirage/pull/163) covers the actual native Environment license writer. The independent ContentId filename policy is already owned by [#74](https://github.com/raleonys/citrine-eclipse-mirage/pull/74).
