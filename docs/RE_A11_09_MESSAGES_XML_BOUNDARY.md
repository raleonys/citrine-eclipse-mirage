## Confirmed shared source-level contracts

- Both message cores list the same 39 registered command/RVA pairs; `dispatch_032d00` requires LSX/Request, id, recipient and first command, consumes only the **first command child**, and rejects an unknown first command or malformed Request siblings. Current [messages tests](../tests/unit/messages/messages_tests.cpp) cover the 39 registrations and multi-command rule; [#117](https://github.com/raleonys/citrine-eclipse-mirage/pull/117) is the existing focused C21 test. Do not create a duplicate or silently reject valid trailing command children.
- Both decode two hex characters per byte, treat an invalid nibble as zero, drop an odd final character, copy XML input up to its first NUL, interpret `has_error` independently of parser return code, retain the code-8 decrypt retry and code-7 one-time empty-version removal, and preserve the selected challenge-response branch. See [`messages_tests.cpp`](../tests/unit/messages/messages_tests.cpp) and [reader tests](../tests/unit/xml_reader/reader_tests.cpp).
- In a pure source path *without* asynchronous delivery receipts, both message cores eagerly pop at most one encrypted event, including when event encryption returns false. The current product's dedicated receipt path has different completion rules below.

## Observed differences and required decisions

| Boundary | Retained donor behavior | Accepted product and status |
| --- | --- | --- |
| **Message exception boundary** | The donor wraps `dispatch_032d00` in a try/catch for `NoResponseRequiredError` (empty output) and `UnknownMessageError` (optional `UnknownMessageEffects::unknown_message_07bd70` diagnostic, then empty output). | Current `process_message_033d70` calls dispatch directly. The concrete [application effects](../src/runtime/application.cpp) throw `std::invalid_argument` for an invalid LSX message; the message core does not translate it to the donor's terminal types. **Source-confirmed contract difference, product bug not established.** Check the actual Asio session error owner and accepted invalid-message policy before proposing changes or a new swallowed-exception fallback. |
| **Async event delivery** | Donor unlock/queue operations use eager `pop_front_locked` following event encryption (even false). | Product adds a `State::delivery` receipt: reserve front before copying event, settle true only after actual write completion and false on failure/cancellation; `Unlock` guards the queue mutex during exceptions. Current [queue integration](../tests/unit/event_queue/integration_tests.cpp), [#143](https://github.com/raleonys/citrine-eclipse-mirage/pull/143) and [#173](https://github.com/raleonys/citrine-eclipse-mirage/pull/173) guard this distinct production ownership. Donor eager dequeue is **not** authorization to drop receipt support. |
| **XML vendor and depth** | Donor adapter constructs a TinyXML2 11 document with preserve-whitespace and the retained package's modified **100-level** depth setting, not an upstream binary identity. | Product uses immutable **pugixml 1.16** and a first-party compatibility scanner, with rejection at 499 nested elements in its present reader test (500-level reference policy). This was an owner-approved product migration in merged [#149](https://github.com/raleonys/citrine-eclipse-mirage/pull/149). Do **not** import the donor's patched TinyXML2 or downgrade the accepted parser limits. |
| **XML tree/attribute values** | Donor stores owning TinyXML2 documents and wraps native nodes; `GetText`, attribute order, C-string truncation and parser diagnostics come from the selected donor library. | Product retains independent pugixml document-owned wrappers, stable decoded attribute/text strings, normalizes line endings, and performs checked entity decoding. [XML backend comparison](XML_BACKEND_COMPARISON.md) defines existing native/differential obligations; the donor's claims alone cannot establish full malformed/locale/allocator equivalence. |

## Deduplication, test gates and disposition

The accepted product already has exact-source unit coverage for registrations, malformed XML, parser retries, actual synthetic router/AES, message queue and reader value ownership. Open [#151](https://github.com/raleonys/citrine-eclipse-mirage/pull/151) supplies application TCP/LSX and finalized-DLL XML acceptance; [#173](https://github.com/raleonys/citrine-eclipse-mirage/pull/173) explicitly tests prepared-response receipt unwind. Neither source/fixture should be duplicated merely to copy donor assertions.

The distinct **unresolved requirement** is what host-visible result and diagnostic are required for a *validly parsed but unrecognized* or handler-rejected LSX message, and whether the current exception propagation is intended at the actual Asio session boundary. A future issue or implementation PR requires a scoped real product/session reproducer, chosen owner policy, an assertion-sensitive regression, and exact-head Windows/Native/Golden evidence as applicable. This document alone is not evidence of a shipping defect.

**Validation boundary:** source byte SHA-256 checks, inspection of the named source branches and manifest entries only; no current-head full Source QA, native MSVC, compiled execution, Golden, donor DLL or Consumer/game tests were run for this documentation change. No production code, reader/vendor policy, ABI/export, CI, test, release or long-lived research branches are modified; no merge is performed here.
